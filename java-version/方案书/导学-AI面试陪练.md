## 项目事实边界

以下内容基于目前已确认的项目描述整理。项目支持本地导入简历，按照项目经历和计算机基础知识生成学习问题，在用户以文字回答后给出评分和改正建议，并支持完整的文字面试模拟。技术栈、模型部署方式、文件格式、数据持久化方式、评分维度和测试数据规模尚未确认，汇报时应补充真实信息，不能直接把下文的“待补”内容说成已经完成。

## 项目技术定位

这是一个以 AI 应用为主、兼具后端工作流和文本交互的项目。核心价值不是“调用一次大模型”，而是把简历事实、知识问题、连续面试流程和回答反馈组织成一个可使用的学习闭环。若目前系统只是固定顺序调用多个 Prompt，应定位为“RAG + 多轮面试工作流”；只有当系统根据面试状态和回答结果进行条件路由、追问或切换任务时，才适合强调 Agent 编排。

## 核心原理解析

### 1. 从简历原文到可检索事实

问题：原始简历包含标题、时间、技术栈和职责混合文本，直接交给模型容易遗漏项目边界或产生无依据追问。

机制：先解析文件，再按教育、实习、项目、技术栈和奖项等语义组织内容，为片段补充来源和类别信息。

项目落点：系统可以基于“FinanceAgent 项目做了什么”“云中摄影用了哪些并发机制”等事实出题，而不是只根据关键词生成泛化八股。

### 2. 检索增强的问题生成

问题：只靠模型记忆生成的问题可能与候选人的真实经历不匹配。

机制：根据当前面试类型检索对应简历事实或知识点，再把有限上下文传给问题生成模块；生成结果需要受题型、难度和个人经历约束。

项目落点：项目面优先检索项目职责和技术栈，八股面优先检索预先准备的知识主题；两类问题使用不同提示和输出格式。

### 3. 面试任务的状态推进

问题：一次完整面试不只是连续问几道题，还要知道当前项目、题目序号、回答是否完成以及是否继续追问。

机制：用显式会话状态表示面试阶段、当前问题、回答历史和下一步动作；根据回答是否为空、是否相关或是否需要深入决定追问、换题或结束。

项目落点：如果你的系统已经按这些条件推进流程，可以将其作为 Agent 的核心证据；如果只是固定顺序调用，应如实称为多轮工作流。

### 4. 基于标准的答案评估

问题：让模型直接输出“回答得很好”缺少解释，也难以帮助用户改进。

机制：先定义评分维度和等级，再要求模型分别给出得分依据、遗漏点、技术纠正和可复述答案；程序使用结构化结果展示，而不是直接渲染一段自由文本。

项目落点：项目面可以检查个人职责、技术机制和结果证据；八股面可以检查概念准确性、适用边界和常见误区。具体维度和权重需要你补充真实实现。

### 5. 文本面试的完整闭环

问题：单题问答只能证明生成能力，不能证明系统能够支撑一次学习过程。

机制：把面试开始、题目生成、回答提交、评分反馈、追问、主题切换和总结报告串成一次会话，保留必要的上下文和历史。

项目落点：当前版本以文本回答为主，不影响项目完整性；汇报时应明确不包含语音识别、语音合成或视频分析。

## 关键设计决策

| 决策 | 备选 | 取舍 | 风险 | 验证方式 |
|---|---|---|---|---|
| 简历事实组织 | 整份简历一次性塞入 Prompt / 分段并带元数据 | 分段更利于检索和定位，工程复杂度更高 | 切分丢失上下文 | 抽样检查问题引用是否来自正确项目 |
| 问题生成 | 纯随机生成 / 按项目和八股路由 | 路由更贴合学习目标 | 路由条件覆盖不足 | 统计不同面试模式的问题类型分布 |
| Agent 形态 | 固定链路 / 条件状态机 | 状态机更能处理追问和结束条件 | 状态膨胀、异常分支多 | 绘制状态图并覆盖空回答、错误回答和结束场景 |
| 评分方式 | 单次自由评价 / Rubric + 结构化输出 | Rubric 更可解释、便于前端展示 | 模型仍可能主观漂移 | 同一回答多次运行并比较评分差异 |
| 知识来源 | 只用模型知识 / 简历与知识库联合检索 | 联合检索更贴合用户事实 | 知识库内容过时或来源不清 | 对关键反馈保留引用片段和来源 |
| 隐私策略 | 上传外部服务 / 本地模型或脱敏后调用 | 本地或脱敏更保护简历隐私 | 本地模型效果和资源消耗 | 检查日志、请求体和错误记录是否泄露个人信息 |

## 量化与验证

当前没有可写入简历的量化结果，建议汇报前补充以下验证，均标为“待测”直到实际完成：

1. **问题相关性**：抽取若干项目，人工判断生成问题是否能回指到对应项目事实；记录相关、部分相关和无关比例。
2. **评分一致性**：准备多组标准回答和边界回答，重复运行评分，观察分数和反馈是否稳定。
3. **反馈完整性**：检查每次评分是否包含分数依据、遗漏点、纠正建议和可复述答案，而不是只有一句结论。
4. **流程覆盖**：覆盖项目面、八股面、空回答、不相关回答、追问、切换主题和主动结束等场景。
5. **模型失败**：模拟超时、空响应、非法 JSON 和检索为空，验证系统是否能提示用户并安全结束当前步骤。
6. **隐私检查**：检查简历原文、手机号、邮箱和模型请求日志，确认不必要的敏感信息没有写入日志或错误页面。
